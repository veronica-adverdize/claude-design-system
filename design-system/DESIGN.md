# Shared Design Principles

These standards apply across all projects in this workspace. They are a quality floor, not a visual theme. Each project owns its own art direction, color palette, typography choices, and component styling.

## Responsive Design

- Mobile-first: design for 320px minimum, scale up.
- Fluid scaling: use `clamp()` for typography and spacing where practical.
- No horizontal page scroll at any supported width.
- Side gutter: 16px minimum on mobile (`--gutter`).
- Test at 320px, 375px, 768px, 1024px, 1280px, and 1536px.

## Accessibility

- WCAG 2.2 AA as the baseline for every surface.
- Semantic HTML: correct heading hierarchy, one `<h1>` per page, landmark regions.
- Keyboard navigation: all interactive elements reachable and operable via keyboard.
- Focus visible: never remove the focus indicator; restyle it to match the project's aesthetic.
- Touch targets: minimum 44×44px on touch devices.
- Color contrast: 4.5:1 for normal text, 3:1 for large text and UI components.
- Reduced motion: respect `prefers-reduced-motion` — see `motion.md` for the approach.
- Screen readers: meaningful `alt` text, `aria-label` where visible text is absent, live regions for dynamic content.

## Typography

- Use the shared fluid type scale from `tokens.css` (`--text-xs` through `--text-4xl`).
- Maximum comfortable reading width: 75ch (`--measure`).
- Proper hierarchy: headings create a scannable outline, not just size variation.
- Projects choose their own typefaces; the shared token `--font-sans` is a system stack fallback.

## Color

- Define color tokens on `:root`.
- Support dark mode via `prefers-color-scheme: dark`, guarded by `:root:not([data-theme="light"])`.
- Explicit `background-color` on `body` — never rely on browser defaults.
- Shared semantic slots (`--color-surface`, `--color-text`, `--color-accent`, etc.) provide the skeleton; projects override values, not names.

## Spacing and Layout

- Use the shared spacing scale (`--space-1` through `--space-24`) for consistent rhythm.
- Predictable interactive states: hover, focus, active, disabled should be visually distinct.
- Consistent component spacing within a project; the scale provides the vocabulary.

## Performance

- No cumulative layout shift from loaded assets: reserve dimensions for images and embeds.
- Lazy-load images below the fold.
- Minimal external dependencies: load scripts only from trusted CDNs, with pinned versions.
- Prefer `transform` and `opacity` for animations — see `motion.md`.

## Per-Project Overrides

Any token in `tokens.css` can be redefined at the project level. The shared file provides defaults and a consistent naming convention. A project's `DESIGN.md` (generated by Impeccable's `document` command) records its specific visual world, palette, and component decisions — that file is authoritative for that project.
